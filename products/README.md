## 폴더 구조

제품 하나당 폴더 하나입니다. 앞의 3종은 시스템의 **제품 지식 매핑(KB) 화면**과 1:1로 대응하고,
뒤의 4종은 제안 현장에서 반복 요구받는 **제안 대응 문서**입니다.

```
products/
├── README.md                 ← 이 파일 (제품 목록 인덱스)
├── 작성가이드.md              ← 제품 담당자 작성 가이드
├── _양식/                     ← 새 제품 폴더 양식 (통째로 복사해서 사용)
│   ├── README.md             ← 제품 문서 양식
│   ├── slides.md             ← 제안 슬라이드 인덱스 양식
│   └── images/README.md      ← 화면 캡쳐 파일명·삽입 규칙
└── <제품·서비스명 한글>/
    ├── README.md             ← 「기능」 제품 설명·기능 계층 (서비스는 수행 활동)
    ├── slides.md             ← 「슬라이드」 요구사항 ↔ 대응 문장 ↔ 원본 ppt 위치
    └── images/               ← 「이미지」 화면 캡쳐 png
```

> 🖥️ **제안 대응 문서 4종(소개서·매뉴얼·사이징·제안대응)은 이 저장소가 아니라
> 영업 지원 스테프 화면에서 입력합니다** — `사이드바 > 영업 지원 스테프 학습 > 제품·서비스 정보`.
> 표가 많아 마크다운으로 채우기 번거롭고 값이 자주 바뀌기 때문입니다.
> 자세한 내용은 [작성가이드.md 4장](./작성가이드.md#4-제안-대응-문서-4종--시스템-화면에서-입력합니다).

> ⚠️ **공개(public) 저장소입니다.** 제안서 원본 pptx·고객 제안 문안·계약 금액·고객 실데이터 화면·
> 제안 슬라이드는 원본 대신 `slides.md` 에 위치만 적습니다.
> 소개서·매뉴얼 원본 파일은 **화면의 해당 탭에 직접 업로드**하세요 (사내 서버 보관).

## 제안 대응 문서 4종은 화면에서

발주처가 반복해서 요구하는 자료(제품 소개서·매뉴얼·서버 사이징·이중화 스펙·요구사항 수용 여부·
M/M 및 일정 산정)는 **영업 지원 스테프 화면에서 입력합니다.**

`사이드바 > 영업 지원 스테프 학습 > 제품·서비스 정보` → 담당 제품·서비스 선택 → 탭 4개

| 탭 | 무엇을 적나 | 대표 질문 |
|----|-------------|-----------|
| 소개서 | 📎 소개서·리플릿 **파일 업로드** + 소개 논리, 차별점, 레퍼런스 | "제품 소개서 주세요" |
| 매뉴얼 | 📎 매뉴얼 **파일 업로드** + 제공 범위, 교육, 기술지원 SLA | "어떤 매뉴얼이 제공되나요" |
| 사이징 | 데이터 용량별 서버 스펙, 이중화 구성·추가 스펙 | "데이터 O TB면 서버 몇 대? 이중화하면?" |
| 제안대응 | 요구사항 수용 여부 판정, M/M 원단위, 표준 일정 | "이 요구사항 되나요? 공수는?" |

작성 현황은 화면 목록에 표시되므로 이 문서에서 따로 관리하지 않습니다.

## 작성 규칙 (요약)

- 폴더명: 제품명을 한글로 (예: `와이즈인텔리전스/`, `와이즈DQ/`)
- 제품 설명은 폴더 안 `README.md` 에 작성 — 기능은 `### 대분류 → #### 중분류 → - **소분류**: 설명` 계층
- 각 문서 하단 **"제안서 작성 시 강조 포인트"** 섹션이 제안서 생성 시 우선 반영됨
- 인증·스펙 변경 시 해당 문서와 루트 `company_profile.json` 을 함께 업데이트
- 제안 대응 문서 4종(화면 입력)은 확인 못 한 값을 빈칸으로 두지 말고 `미보유`·`별도 협의`·`확인 중` 으로 상태 표기
- 새 제품·서비스 추가 시 `_양식/` 폴더 복사 → 작성 → 이 README 목록에 추가.
  화면 쪽에도 관리자가 `제품·서비스 정보 > 제품·서비스 등록` 으로 같은 code 를 등록해야 합니다
- 상세는 [작성가이드.md](./작성가이드.md)
