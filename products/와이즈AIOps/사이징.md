## 4. 이중화(HA) 구성

### 4.1 이중화 방식

| 대상 컴포넌트 | 지원 방식 | 추가 서버 | RTO(절체 시간) | RPO(데이터 손실) | 비고 |

| [애플리케이션] | [Active-Active] | [+1대] | [무중단] | [없음] | [L4/로드밸런서 필요] |

| [파일 저장소] | [공유 스토리지] | [—] | | | [NAS/SAN 필요] |

### 4.2 이중화 시 스펙 산정 규칙

> "이중화하면 서버가 두 배냐"는 질문에 답하는 부분입니다.

- **Active-Standby:** 단일 구성과 **동일 사양 1식 추가**. 평상시 대기 노드는 부하를 받지 않음
- **Active-Active:** 노드당 부하가 분산되므로 노드별 사양은 [단일 구성의 O%] 수준으로 산정 가능.
  단, **1노드 장애 시에도 전체 부하를 감당**해야 하므로 노드당 최소 [O%] 이상 확보 권장
- **추가 필요 요소:** [로드밸런서 / 공유 스토리지 / 세션 클러스터링 / 가상 IP] 등
- **라이선스:** 이중화 시 라이선스 추가 필요 여부 → [필요 / 불필요 / Standby는 무상] (아래 7장 참조)
